# 股票健診

輸入股票代號，30 秒看懂：**現在能不能買、在哪買、買多少、錯了在哪停損**。

每天抓取台股（上市／上櫃）與美股資料，從**趨勢、動能、量價、基本面、籌碼**五個面向評分，
提供評等、操作建議、進場區／停損／目標價、建議部位大小，並用歷史資料驗證模型在每一檔股票上準不準。

提供兩種用法：**網站**（可部署到 Render）和**命令列**（每天產生 HTML 報告）。

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/WillChiou6529/stock-checkup)

## 網站功能

| 頁面 | 內容 |
|---|---|
| 首頁 | 搜尋（代號或中文名稱）、大盤概況與三大法人、我的自選股排行、今日選股精選 |
| 個股健診 | 0~100 健診分數、利多／利空摘要、**新手五問**（能買嗎／在哪買／錯了怎麼辦／目標在哪／買多少）、互動 K 線圖（均線、布林、停損／目標線、技術分／RSI／KD／MACD 副圖）、每條加減分理由、交易計畫、部位計算機、持股健診、關鍵指標白話解釋、基本面、籌碼、模型回測 |
| 今日選股 | 全市場篩選「法人連續買超 + 營收成長 + 估值合理」，逐檔健診後排序 |

自選股、持股成本、資金設定都存在使用者自己的瀏覽器（localStorage），不需要註冊帳號。支援手機與深色模式。

### 績效追蹤

`/#/track`：每個交易日 21:30 由 GitHub Actions 自動對約 90 檔股票做健診並記錄（`data/signals.csv`），
之後計算每個建議 5／20／60 日後比大盤多賺多少、勝率、觸及停損或目標的比例（`data/track.json`）。
同一個排程也會累積內部人申報與重大訊息（官方 API 只提供當天資料）。網站直接讀 GitHub 上的 `data/`，資料更新不需要重新部署。

手動執行：`python -m jobs.daily`

### 研究：完整模型回測（無存活者偏差）

python research/dataset.py       # 下載 2021 年起每日全市場行情（含已下市股票）、除權息、月營收、月底估值與籌碼（第一次約 1.5 小時）

結果顯示在「怎麼看懂」與「績效追蹤」頁。

1. 點上方「Deploy to Render」按鈕（或在 Render 選 **New → Blueprint**，選這個 repo）

3. 部署完成後就能用 `https://<服務名稱>.onrender.com` 開啟

## 命令列：每日報告

```
雙擊「每日執行.bat」
```
或命令列：
```
python analyze.py                 # 分析自選股 + 全市場掃描
python analyze.py 2330 6488 NVDA  # 只分析指定股票
python analyze.py --no-scan       # 不做全市場掃描
python validate_model.py          # 重新驗證模型（約 1 分鐘，建議每月跑一次）
```
執行完成後會自動開啟 `reports/YYYY-MM-DD.html`。

**自動每日執行**：雙擊「設定每日排程.bat」，會在週一到週五 21:30 自動跑。
選 21:30 是因為三大法人約 16:00 公布、融資融券約 21:00 公布，21:30 之後資料最完整。
盤中也可以執行，但最新一根 K 棒會是即時價。

需求：Python 3.8+、pandas、numpy，不需要其他套件和 API 金鑰。

## 設定（config.json）

| 欄位 | 說明 |
|---|---|
| `watchlist` | 自選股。台股填代號（`2330`、`0050`、`6488`），美股填 ticker（`NVDA`） |
| `holdings` | 持股，會額外給出續抱／減碼／停損建議。例：`{"2330": {"cost": 1500, "shares": 1000}}` |
| `capital` | 投資總資金，用來計算建議部位 |
| `risk_per_trade_pct` | 單筆最大虧損占總資金 %（預設 1%：觸及停損時最多虧 1 萬元） |
| `max_position_pct` | 單一持股最多占總資金 % |
| `chip_lookback_days` | 法人與融資觀察天數 |
| `scan.enabled` / `top_n` | 是否做全市場掃描、要挑出幾檔 |
| `scan.min_trade_value_million` | 掃描的最低成交金額（百萬元），用來排除冷門股 |

## 評分方式

| 面向 | 權重 | 內容 |
|---|---|---|
| 趨勢 | 30% | 股價和均線（MA20/60/120/240）的相對位置、均線排列、季線斜率、ADX、**12-1 月中期動能** |
| 動能 | 20% | RSI、MACD、KD、20 日漲跌、相對大盤強弱 |
| 量價 | 10% | OBV 與股價是否背離、帶量漲跌、上漲日和下跌日的量比、帶量突破 |
| 基本面 | 22% | 月營收年增、累計營收、本益比（搭配成長率看 PEG）、殖利率、淨值比、今年 EPS 年化 vs 近四季 |
| 籌碼 | 18% | 外資／投信 5 日買賣超占成交量比例、投信連買天數、法人合計、融資增減和股價的關係、券資比 |
| 風險控管 | 不計分 | 乖離、波動度、距高點、大盤位階。只用來提醒追高、調整操作建議 |

- 總分 ≥72 買進、60~72 逢回分批布局、45~60 觀望、35~45 減碼、<35 賣出／避開
- 趨勢分數 <35 時，即使總分高也會降為觀望，避免逆勢摸底
- ETF 和美股沒有基本面與籌碼分數，權重會按比例分給技術面
- 報告中點開每個面向，可以看到每一條加減分規則和它的理由

### 為什麼「風險控管」不計入總分？

`validate_model.py` 的橫斷面檢定（75 檔台股，2022/10～2026/10）顯示：

| | 未來 20 日 IC | 未來 60 日 IC |
|---|---|---|
| 技術總分 | **+0.067**（t=2.4） | **+0.087** |
| 趨勢 | +0.070 | +0.095 |
| 動能 | +0.048 | +0.053 |
| 量價 | +0.043 | +0.050 |
| 風險控管 | −0.056 | −0.122 |

技術分五分位（每天依分數分 5 組）的 60 日相對報酬，由低到高分別是
−3.8%、−1.8%、+0.3%、+1.2%、+4.1%，分數越高表現越好。
風險分數的預測力是負的（被扣分的過熱或高波動股，事後反而表現較好），
所以只把它當作部位控管工具，不用來判斷多空。

### 交易計畫怎麼算

- **停損**：取最近支撐（3 ATR 以內）往下 0.5 ATR，並限制在現價 −1.5~−3 ATR 之間
- **目標 1**：最近的壓力價，如果太近就用 2 倍風險；**目標 2**：3 倍風險或下一個壓力
- **建議部位**：取以下兩者較小的一個
  - 資金 × 單筆風險% ÷（現價 − 停損）
  - 資金 × 單一持股上限
- **移動停利**：22 日高點 − 3×ATR（Chandelier Exit），持股跌破時建議出場

### 「這套模型在這檔股票上準不準？」

每檔股票都會用自己的歷史計算：技術分高或低的時候，之後 20 日相對大盤的超額報酬和跑贏機率。
如果 IC 是負的，報告會直接告訴你這檔股票的技術訊號要打折看待。

## 資料來源

- 價格：Yahoo Finance（5 年日線，還原權息）
- 台股估值、月營收、EPS：證交所／櫃買中心 OpenAPI
- 三大法人、融資融券、大盤法人金額：證交所／櫃買中心網站 JSON

證交所對大量請求會封 IP，程式每次請求間隔 2.2 秒，歷史日期的資料會永久快取在 `cache/`
（超過 30 天自動清除）。第一次執行約 1~2 分鐘，之後通常十幾秒內完成。

## 輸出檔案

- `reports/YYYY-MM-DD.html`：每日報告
- `signals_history.csv`：每日每檔的評分紀錄（可用 Excel 開啟，用來追蹤分數變化和建議的事後表現）
- `model_card.json`：模型驗證結果，報告會引用

## 限制

- 基本面和籌碼沒有可取得的每日歷史，這兩個面向的權重是經驗設定，**沒有經過回測**
- 驗證樣本是目前仍在交易的權值股，有存活者偏差；樣本期間大多是多頭市場
- 美股只有技術面
- 本程式僅供研究參考，不構成投資建議
